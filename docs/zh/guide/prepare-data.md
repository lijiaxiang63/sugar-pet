# 准备数据

在正式跑分析前花十分钟把数据整理规范，后面能省掉很多麻烦。运行分析通常需要三类输入：配准到 MNI 空间的图像、一组健康对照，以及（可选的）年龄和性别信息表。

## PET 图像

* **文件格式**：NIfTI 格式（`.nii` 或 `.nii.gz`），每位受试者对应一幅静态 FDG-PET 图像。
* **图像空间**：除了“空间标准化”页面之外，其余所有页面都要求图像已经配准到 MNI 空间（体素大小和包围盒不限）。如果图像还在扫描仪原始空间，可以先跟着[第 1 步](../tutorial/spatial)做空间标准化。
* **网格一致**：同一个参考库里的所有对照图像，其体素大小和矩阵维度必须完全一致。只要它们是用同一套流程配准出来的，通常自然满足这个条件。
* **关于平滑**：不要提前手动平滑图像。需要平滑的步骤（如计算因子、Z 值图或组间比较）软件内部会自动处理（默认 8 mm），而**强度归一化**输出的结果图像本身是未平滑的。如果你的图像在导入前已经平滑过，记得在界面要求填写平滑核的地方设为 `0`。

::: warning 务必逐幅检查配准质量
只依赖 PET 图像做空间标准化时，偶尔会出现配准跑偏但软件并未报错的情况。正式分析前，强烈建议用看图软件（如 MRIcroGL、FSLeyes、ITK-SNAP 或 SPM 的 Check Reg）把配准后的图像逐张看一遍，确认大脑没有变形、歪斜或被裁切。
:::

## 健康对照组

直方图归一化、Z 值图、帕金森分类和参考簇，都需要以健康对照组作为基准。对照组图像应当来自**同一台扫描仪**、采用**相同的重建参数**，并经过完全一致的预处理。

| 对照组例数 | 适用范围 |
| --- | --- |
| 少于 3 例 | 无法建立参考库（软件会拒绝执行） |
| 3 ~ 9 例 | 可以估算 HN、iPS、iHN 的归一化因子，但体素级统计不够稳健 |
| 20 例以上 | 推荐用于 Z 值图和组间比较 |
| 30 例以上 | 推荐用于单病例帕金森分类 |

## 年龄与性别表（协变量） {#covariates}

大脑对 FDG 的摄取会随年龄变化，男女之间也存在细微差异。提供一张记录年龄和性别的表格，就能在分析中校正这些协变量（见 [W 值](../tutorial/zmap#z-or-w)）。表格支持 TSV 或 CSV 格式，直接复用 BIDS 规范的 `participants.tsv` 即可：

```
participant_id	age	sex
sub-hc01	63	F
sub-hc02	58	M
sub-pt01	71	M
```

* 软件默认按 `participant_id` 匹配图像文件，例如 `sub-pt01` 会自动对应 `sub-pt01_space-MNI_pet.nii.gz`；也可以在表里加一列 `image` 来直接指定文件名。
* 软件只会读取你在界面上勾选的列。纳入校正的列必须是连续数值（如年龄），或是只有两种取值的分类变量（如 `F` 和 `M`）。
* 患者和对照组的信息可以放在同一张表里，如上面的示例所示。

## 文件命名规范

软件沿用 BIDS 风格，根据输入文件名自动生成输出文件名：

| 输入文件名 | 生成的输出文件 |
| --- | --- |
| `sub-pt01_space-MNI_pet.nii.gz` | `sub-pt01_space-MNI_desc-hn_pet.nii.gz`（HN 归一化后的图像） |
| | `sub-pt01_space-MNI_desc-hn_zmap.nii.gz`（Z 值图） |
| | `sub-pt01_space-MNI_report.html`（分类报告） |

因此，每幅输入图像都必须有唯一的文件名。如果不同文件夹下存在同名文件（例如 `a/pet.nii.gz` 和 `b/pet.nii.gz`），它们会映射到同一个输出文件名——在“空间标准化”和“帕金森综合征分类”页面，程序会直接报错并停止运行；在其他页面，后处理的结果则会覆盖先处理的结果。

## 推荐的目录结构 {#layout}

后面的教程会采用下面这种目录结构来组织文件。虽然不是强制要求，但把输入和输出分开放会清晰得多：

```
study/
├── raw/                原始空间的图像（仅在未做空间标准化时需要）
├── patients/           sub-pt01_space-MNI_pet.nii.gz, ...
├── controls/           sub-hc01_space-MNI_pet.nii.gz, ...
├── participants.tsv    所有受试者的年龄和性别信息
│
├── hc_reference/       第 2 步生成的参考库
├── normalised/         第 3 步生成的归一化图像
├── zmaps/              第 4 步生成的 Z 值图 / W 值图
├── reports/            第 5 步生成的分类报告
└── compare/            第 6 步生成的组间比较结果
```

### 一键创建 {#create-it}

这些文件夹不用手动一个个建。打开侧边栏第一项**研究文件夹**页面，选好研究文件夹的存放位置和名称，点击**创建文件夹**即可：

<Shot name="study" alt="创建完成后的“研究文件夹”页面" />

页面会列出每个文件夹及其用途，并标明它是*已创建*还是*原已存在*。同时，应用会把这个研究文件夹作为之后写入结果的地方：各页面的输出文件夹会自动设为研究文件夹里对应的那一个，不用再逐页选择；下次启动时应用也会记住它。只有“空间标准化”的输出需要你自己选，因为患者和对照要分别写入不同的文件夹。

如果研究文件夹的 `hc_reference/` 里已经有建好的参考库，而当前没有选参考库，它就成为当前参考库。当你为另一个研究创建文件夹时，各页面会整体切换过去：属于上一个研究的图像、表格和参考库都会从各页面移除，以免把一个研究的图像写进另一个研究，或拿去和另一个研究的对照比较。你从别处选的图像和参考库则保持不变。

在命令行里，用下面的命令创建这些文件夹：

```bash
sugar-pet init study/
```

两种方式都会建好上面的文件夹，并生成一个只含表头 `participant_id`、`age`、`sex` 的 `participants.tsv`，等你填写。已经存在的内容不会被改动，所以对已经开始使用的研究文件夹也可以放心运行：只会补上缺少的部分。

### 各个文件夹的作用 {#what-each-folder-is-for}

前四项需要你在运行分析之前准备好：

| 文件夹或文件 | 放什么 |
| --- | --- |
| `raw/` | 仍在原始扫描空间的图像。只有图像尚未配准到 MNI 空间时才需要：[第 1 步](../tutorial/spatial)把它们配准后写入 `patients/` 和 `controls/`。 |
| `patients/` | MNI 空间的患者图像，每人一幅。 |
| `controls/` | MNI 空间的健康对照图像，须与患者来自同一台扫描仪、经过相同的预处理。 |
| `participants.tsv` | 所有受试者（患者和对照）的年龄和性别，每人一行（见[上文](#covariates)）。 |

其余几个由各项分析写入。应用在创建研究文件夹时，会把它们各自设为对应页面的输出文件夹；在命令行里则传给 `-o`：

| 文件夹 | 由谁写入 | 内容 |
| --- | --- | --- |
| `hc_reference/` | [参考库](../tutorial/build-reference)（第 2 步） | 用健康对照建立的参考库，其他步骤大多要用到它。 |
| `normalised/` | [强度归一化](../tutorial/normalize)（第 3 步） | 归一化后的图像和 `factors.tsv`。 |
| `zmaps/` | [Z 值图](../tutorial/zmap)（第 4 步） | 患者的 Z 值图或 W 值图。 |
| `reports/` | [帕金森综合征分类](../tutorial/classify)（第 5 步） | 患者的分类报告。 |
| `compare/` | [组间比较](../tutorial/compare)（第 6 步） | 患者与对照比较的 T 图和团块表。 |
